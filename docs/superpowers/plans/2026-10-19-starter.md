# Wine Judgment Lab Starter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working offline research starter and publication materials.

**Architecture:** A standard-library Python package validates original dossiers,
builds randomized identity variants, binds imported judgments to hashes and
summarizes paired label changes. A separate module assigns estate-level splits
and evaluates a training-only modal tier baseline.

**Tech Stack:** Python 3.11+, unittest, JSON/JSONL, no core dependencies.

**Spec:** `docs/protocol.md`, derived from the agreed two-experiment discussion.

## Global Constraints

- Work only in this new project directory; leave the bot and brief-engine alone.
- Offline core; no credentials, paid calls, scraping or public uploads.
- Fictional example data must stay labeled synthetic and cannot become findings.
- Publishing requires confirmed account namespaces and working authentication.
- Runtime output uses create-only paths; provenance is part of each trial.

## Task 1: Identity experiment — complete

Files: `wine_judgment_lab/experiment.py`, `tests/test_experiment.py`.

- [ ] Write tests for identical evidence across variants, deterministic random
  order, missing evidence, identity leaks, complete judgment pairs and hashes.
  Example contract: `assert len(build_trials(dossiers, rubric, seed=19)) == 6`.
- [ ] Run `python3 -m unittest discover -s tests -v`; expect missing-module errors.
- [ ] Implement `validate_dossiers(rows)`, `build_trials(rows, rubric, seed)`,
  `analyze(trials, judgments)` with strict input validation and paired counts.
  `build_trials` produces three variants per dossier; `analyze` rejects stale
  hashes and duplicate or missing criterion/variant observations.
- [ ] Rerun focused tests and inspect evidence hashes and literal paired counts.
